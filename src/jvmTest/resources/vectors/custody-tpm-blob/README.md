# Custody-tpm-blob vectors

ADR-0021's custody-tpm-blob suite: the TPM-sealed key blob of `custody/tpm`,
and the blobs a parser must refuse. These are **codec** vectors. Each object's
sealed public and private parts are fixed opaque bytes, not real TPM output, so
the suite needs no TPM and is byte-pinned: re-marshalling the inputs must
reproduce `blob` exactly. The seal/unseal round trip itself is the `tpmsim`
test, which cannot be pinned (the TPM randomises its sealing).

Four cases, every combination of one X25519 object or an X25519 object plus the
named Ed25519 objects `member` and `ssh-ca`, under policy kind 1 or kind 2:

| case | policy | objects |
|---|---|---|
| `x25519-pcr` | PolicyPCR over PCR 7, with PolicyAuthValue | x25519 |
| `x25519-ed25519-pcr` | PolicyPCR over PCRs 0, 7, 11, no authValue | x25519, member, ssh-ca |
| `x25519-authorize` | PolicyAuthorize over PCRs 7, 11, with PolicyAuthValue | x25519 |
| `x25519-ed25519-authorize` | PolicyAuthorize over PCRs 7, 11, with PolicyAuthValue | x25519, member, ssh-ca |

The fixed inputs: the X25519 seed `20 21 … 3f`, `member` the counting seed
`00 01 … 1f` and `ssh-ca` `40 41 … 5f` (each object's `seed` is listed so a port
can re-derive `public_key`; **no seed is in the blob**); PCR *i*'s value is 32
bytes of `0xc0 + i`; the policy-signing key name is `00 0b e0 e1 … ff`; object
*j*'s sealed public part is 48 bytes counting up from `0x80 + 16j`, its sealed
private part 96 bytes from `0xa0 + 16j`.

The blob layout (all integers big-endian):

    magic 31 "void-which-binds-tpm-sealed-v1\0"
    | policy kind 1 (0x01 PolicyPCR, 0x02 PolicyAuthorize)
    | flags 1 (bit 0: PolicyAuthValue also required; other bits zero)
    | pcr bank 2 (0x000B, SHA-256 only) | pcr count 1 | count x pcr index 1 (ascending, < 24)
    | kind 1: count x pcr value 32
    | kind 2: key name length 2 | key name (0x000B then a 32-byte SHA-256 digest)
    | object count 1 (>= 1)
    | count x (kind 1 | name length 1 | name | public key 32
               | sealed public length 2 | sealed public (1..2048)
               | sealed private length 2 | sealed private (1..2048))

Key kinds are `0x01` x25519 and `0x02` ed25519, as in the sealed-file blob: the
X25519 object, if any, comes first with an empty name, and every Ed25519 object
has a distinct non-empty UTF-8 name. A kind 1 policy with no PCRs must require
the authValue, and a kind 2 policy needs at least one PCR. There is no
generation byte. `recipient_id` and `signer_ids` are read from the clear public
keys, without the TPM.

`refusals` lists blobs a parser must refuse, each with the error kind expected:
`unknown-magic` (including heyarr-core's gen1 `heyarr-tpm-sealed-x25519-v1`
magic, which the library never reads), `unknown-policy-kind` (a kind byte other
than 0x01 and 0x02), or `malformed` (everything else: unknown flags, another
PCR bank, a PCR out of range, out of order or twice, a policy that binds
nothing, a bad signing-key name, no objects, an unknown key kind, the layout
rules, an empty or oversized sealed part, truncation and trailing bytes).

Generated by `go test ./custody/tpm -run TestTPMBlobVectors -update` and
otherwise replayed. All keys are test-only.
