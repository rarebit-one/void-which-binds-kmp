# Custody-sealedfile vectors

ADR-0021's custody-sealedfile suite: the passphrase-sealed file blob of
`custody/sealedfile`, and the blobs an opener must refuse.

`device-floor.json` seals two objects, an X25519 seed (`20 21 … 3f`, no name)
and the `device` Ed25519 seed (the counting seed `00 01 … 1f`, the same one the
custody-signer suite signs with), under the passphrase
`correct horse battery staple`, the salt `80 81 … 9f` and the nonce
`c0 c1 … d7`, at the KDF floor (Argon2id, time 3, 256 MiB, parallelism 1).
Argon2id and XChaCha20-Poly1305 are deterministic given those, so `blob` is
byte-pinned: re-sealing the inputs must reproduce it exactly.

The blob layout (all integers big-endian):

    magic 32 "void-which-binds-sealed-file-v1\0" | kdf id 1 (0x01 Argon2id)
    | time 4 | memory KiB 4 | parallelism 1 | salt 32 | nonce 24 | count 1
    | count x (kind 1 | name length 1 | name | public key 32)
    | XChaCha20-Poly1305( count x (kind 1 | name length 1 | name | seed 32) )

Kinds are `0x01` x25519 and `0x02` ed25519. Everything before the ciphertext is
the AEAD's additional data. `recipient_id` and `signer_ids` are read from the
clear public keys, without the passphrase.

`refusals` lists blobs that must not open, each with the passphrase to try and
the error kind expected: `open-failed` (a wrong passphrase, a changed header
byte, a changed ciphertext byte: one error, no hint which), `below-floor`,
`above-ceiling`, `unknown-magic`, `unknown-kdf` or `malformed` (truncated, or a
trailing byte). A row with `before_derivation: true` must be refused from the
clear header alone, without asking for the passphrase or running Argon2id: KDF
parameters are bounded by a floor (time 3, 262144 KiB, parallelism 1) and a
ceiling (time 16, 2097152 KiB, parallelism 4), and an opener refuses either side
before deriving anything.

Generated by `go test ./custody/sealedfile -run TestSealedFileVectors -update`
and otherwise replayed. All keys and the passphrase are test-only.
